### 1.2 冲突裁决顺序

`产品功能规划` > `信息架构` > `设计规范` > `高保真稿`。

- 功能与页面结构冲突，以产品为准；页面内区块冲突，以信息架构为准；视觉数值冲突，以设计规范为准；稿子与规范不一致，一律按规范改稿，而不是反过来改规范。
- 发现任何两份文档互相矛盾：**停下上报主控**，不自行选一个执行（这条同时是 `dev-super.md` 的既有约定）。

### 1.3 变更流程

先改文档，再改代码。任何偏离规范的实现都要求先把规范升版（v1.2 → v1.3 的既有做法），代码里不允许出现「文档没写但我按经验定的」数值。

## 2. 技术栈

### 2.1 两端选型

| 层 | Android | iOS | 说明 |
| --- | --- | --- | --- |
| 语言 | Kotlin 2.x | Swift 6 | 不做跨端共享运行时 |
| UI | Jetpack Compose + Material3（**只取组件骨架，视觉全按设计规范**） | SwiftUI | 不引入第三方 UI 主题库，避免两套视觉漂移 |
| 本地库 | Room（SQLite） | GRDB（SQLite） | 两端 schema 同构，见第 4 章 |
| 异步 | Coroutines + Flow | async/await + AsyncSequence | — |
| 依赖注入 | Hilt | 手写 `AppEnvironment` 容器 | iOS 不引第三方 DI，减少编译期风险 |
| 相机 | CameraX（`PreviewView` + `ImageAnalysis`） | AVCaptureSession + AVCapturePhotoOutput | 取景框与快门按 P17 稿 |
| OCR | **端侧离线**，方案见 2.3 | Vision `VNRecognizeTextRequest`（`zh-Hans`，`.accurate`） | iOS 走系统能力，天然零联网 |
| 图片 | 自研裁剪（Corner 拖拽）+ 本地 JPEG | 同 | 裁切框四角按 P18 稿，橙色 `--warnfg` |
| 备份导出 | SAF `ACTION_CREATE_DOCUMENT` + `Intent.ACTION_SEND` | `fileExporter` + `UIActivityViewController` | 走系统面板，App 不接网盘账号 |
| 备份导入 | SAF `ACTION_OPEN_DOCUMENT` | `fileImporter` | 目录空态跟随系统面板（IA 5.4 第 18 行） |
| 设置存储 | DataStore（Preferences） | `UserDefaults` | 主题、考试范围、清空时间戳 |
| 日志 | Timber（release 关闭） | `os.Logger`（release 降级） | 不落任何学习内容到日志 |
| 静态检查 | ktlint + detekt | SwiftLint + SwiftFormat | Android 本机门禁；iOS CI 阻断 |
| 单测 | JUnit5 + Turbine + Robolectric | XCTest | 见第 11 章 |
| UI 测试 | Compose UI Test + Roborazzi（截图） | XCTest + `swift-snapshot-testing` | 基线图见 11.2；Android 截图命令见 13 |

### 2.2 版本下限

- Android：`minSdk 26`（Android 8.0），`targetSdk 35`，`compileSdk 35`。
- iOS：`iOS 15.0`（Vision / SwiftUI 能力齐备；不用 SwiftData，避免被 17+ 卡住）。
- 之所以钉 26 / 15：这两条线之上 CameraX、SAF、Vision 中文识别都能稳定工作，往下要额外兜底旧机型的相机与文件权限，MVP 不做。

### 2.3 Android 端侧中文 OCR 的取舍（**技术风险点；代理小样已测，真机测试后置**）

验收入口是「拍照识别」，但验收第 19 条把联网锁死在两处（题库获取/更新、备份存网盘），所以 OCR 不能联网。

| 候选 | 是否零联网 | 体积 / 精度 | 结论 |
| --- | --- | --- | --- |
| PaddleOCR mobile（PP-OCRv4 det+rec，Paddle-Lite / ncnn 内置） | 是（模型随包） | 模型约 8–15MB，中文卷面识别可用 | **首选**，需装机实测 |
| Tesseract + `chi_sim` | 是 | 约 30–40MB，卷面精度偏弱 | 备选 |
| ML Kit `text-recognition-chinese` | **否**：中文模型需首次下载 | 精度好、体积小 | 只有在产品愿意新增「第三处联网」时才可选，且必须先在界面上单独提示；**当前口径下不采用** |

落地要求：

1. 代理小样已给出「题干 + 四选项是否完整」通过率的**临时注记**：代理引擎（Windows.Media.Ocr，系统自带、离线）跑 20 张真实卷面为 18/20＝90%，原始数据与限制见 `docs/OCR实测记录.md`。该数字是代理实测，不是 App 端侧引擎实测，**不得写成「90% 达标」**；验收第 9 条据此保留「代理实测 18/20＝90%，App 端侧引擎待真机复测」注记，不编数字、不改口。
2. 真机 OCR 测试（Android 装 PaddleOCR mobile 跑同一组 20 张、iOS 用 Vision `zh-Hans` 同批复测）**后置到功能开发完成之后**再做（用户 2026-11-17 拍板）。届时才用真机结果替换代理注记并回填验收第 9 条，取两端较差者为基线；在此之前不得以代理数字宣称验收达标。
3. 小样不达标就换候选，**不许**为了精度偷偷打开联网识别；要联网必须先改产品第 19 条。
4. 识别结果一律进 P19 的可编辑文本框，缺字走手动补字（决策 3：不做纯手打新建空白录入题）。

## 4. 数据层

### 4.1 表结构（两端同构，字段名一致）

| 表 | 关键字段 | 说明 |
| --- | --- | --- |
| `idiom` | `id`(TEXT,uuid) `word` `pinyin` `initials` `sense` `origin` `color`(褒/贬/中) `pitfalls`(JSON) `synonyms` `antonyms` `frequency`(INT) | `initials` 是预计算的拼音首字母串，搜索用；**内容表** |
| `exam_scope` | `id` `type`(国考/省考/事业编/教师编) `province`(NULL) `enabled`(BOOL) | 省考可多行（省份）；教师编 `enabled` 恒 false |
| `idiom_scope` | `idiomId` `scopeId` | 多对多 |
| `example` | `id` `stem` `optionA..D` `answer` `explain` `examType` `year` `region` `questionType` `imagePath`(NULL) | 解析只有一句（决策 5）；系统自带题库，**内容表** |
| `example_idiom` | `exampleId` `idiomId` | 一题多成语（B3） |
| `user_example` | `id`(TEXT,uuid) `imagePath`(NULL) `ocrText`(NULL) `stem` `optionA..D` `myAnswer`(NULL) `isMistake`(BOOL) `examType`(NULL) `year`(NULL) `region`(NULL) `createdAt` | **用户拍照录入题，属用户数据**（v1.5 新增）；`isMistake=false` 为纯录入题，`true` 为用户标错的录入题；不随题库包导入/替换（§4.6） |
| `user_example_idiom` | `userExampleId`(FK→`user_example.id`) `idiomId`(FK→`idiom.id`) | 录入题与成语的多对多关联（v1.7 新增），一题多成语、P20 可多选、**至少一条**；保存时与 `user_example` 同一事务写入全部勾选；决定录入题归属哪个成语，不进错题列表；用户表，绝不随题库包导入/替换（§4.6） |
| `mistake` | `id` `userExampleId`(FK→`user_example.id`) `imagePath`(NULL) `ocrText`(NULL) `stem` `optionA..D` `myAnswer`(NULL) `reason`(NULL) `tagNames`(JSON) `examType` `year` `region` `state`(待复习/已掌握) `createdAt` `lastReviewedAt` `reviewCount` | 错题 = 用户录入题中 `isMistake=true` 的标记/子集；正文列（`stem`/`optionA..D`/`myAnswer`/`imagePath` 等）为 `user_example` 的快照（历史兼容），**事实源是 `user_example`**；标错时才生成此行 |
| `mistake_idiom` | `mistakeId` `idiomId` | 归属关系，**至少一条**；与 `user_example` 的关联通过 `mistake.userExampleId` |
| `review_log` | `id` `mistakeId` `result`(对/错) `at` | 只服务本机统计（假设 10） |
| `idiom_state` | `idiomId` `status`(未学/学过/已掌握) `favorite`(BOOL) | A6 / A7 |
| `settings` | `key` `value` | 主题、清空时间戳等 |

本版数据模型共 **12 张表**（v1 基线 10 张 + v2 新增 `user_example` + v3 新增 `user_example_idiom`）；全文检索虚表 `idiom_fts` 不计入数据表数。12 张表中，**内容表**（题库包可替换）为 `idiom` / `idiom_scope` / `example` / `example_idiom` 共 4 张；**用户表**（绝不触碰）为 `exam_scope` / `user_example` / `user_example_idiom` / `mistake` / `mistake_idiom` / `review_log` / `idiom_state` / `settings` 共 8 张（§4.6 导入隔离据此划分）。

硬约定：

- 主键一律 uuid 字符串，**不用自增**——备份合并要靠它去重（见 4.3）。`user_example.id` 由 App 本机生成。
- 时间一律 UTC ISO-8601 字符串存库，展示时转本地时区。
- `state` 只有两个值；「待复习」不是由时间算的，MVP 不引记忆算法（假设 5：队列按最近录入优先）。
- `user_example.isMistake` 是本版新增的**标错标记**：拍照保存时默认 `false`（纯录入题），仅当用户在 P20 勾选「是否做错」才置 `true` 并同时生成一条 `mistake`；未标错的录入题不进错题列表（C6），但在对应成语详情「我的录入题」区可见。
- `mistake.userExampleId` 为外键，标错生成的错题必须指向存在的 `user_example` 行；删除错题只删标记行及其 `review_log` / `mistake_idiom`，**不删 `user_example` 录入题**。历史数据该列可空，导入旧备份时按 `stem` 无法自动回填则保持 NULL（历史兼容口径）。
- `user_example_idiom` 是录入题归属成语的唯一事实源（v1.7）：保存时必须与 `user_example` 同事务写入全部勾选（至少一条）；删除错题只删 `mistake` 标记行，不动本表；清空数据一并清空。`mistake_idiom` 仍按原口径在标错时同步写入（错题归属快照），查询错题按 `mistake_idiom`，查询录入题按 `user_example_idiom`。
- 图片只存相对路径（`images/<录入题id>.jpg`，id 为 `user_example.id`），不存绝对路径——iOS 沙盒路径会随安装变化。`mistake.imagePath` 保留为快照列，与 `user_example.imagePath` 指向同一文件。（备份包已拍板不含原图，见 4.3；这里的相对路径指本机保存的拍照原图，不随备份导出。）

### 4.2 检索实现

- 成语搜索（A3）走 FTS（Room FTS4 / GRDB FTS5），索引列：`word`、`pinyin`、`initials`、`sense`。
- 支持四种输入：完整成语、单字、全拼、首字母；单字走前缀 LIKE + FTS 组合，不做分词库。FTS 查询须按平台语法构造：Android FTS4 用列级 MATCH，前缀星号在 phrase 引号内；iOS FTS5 前缀星号在引号外。用户输入作为绑定参数，转义引号并拒绝 NUL；单测须独立验证 FTS 路径，不能只靠 LIKE 兜底通过。
- 例题、用户录入题与错题列表按 `createdAt` 倒序，分页 50 条；成语库 1,286 条一次性进内存做分组，不分页。用户录入题的「我的录入题」区按当前成语 JOIN `user_example_idiom` 过滤 `user_example`（v1.7），不进 FTS 搜成语库（FTS 扩展列二期）。

### 4.3 备份包格式（技术约定，供 P15 / P22 / P23）

```
backup-YYYYMMDD-HHMMSS.zip
├── manifest.json      # schemaVersion, appVersion, build, exportedAt, counts, sha256
└── data.json          # mistakes / userExamples / reviews / idiomStates / scopes / tags
```

- **已拍板：备份包不含原图**。不打包 `images/` 目录，manifest 不含 `imagesIncluded` 字段。导入时 `mistake.imagePath` 与 `user_example.imagePath` 一律置空，P10 的图片位显示「原图已不在」（橙 `--warnfg`，设计规范 5.7）。影响须写明：换机 / 恢复备份后原图位必然显示占位，原图无法从备份还原，需用户自行保留原始照片或重新拍照。
- **`userExamples[]`（v1.5 新增；v1.7 增 `idiomIds`）**：字段同 §4.1 `user_example`（含 `id` / `imagePath` / `ocrText` / `stem` / `optionA..D` / `myAnswer` / `isMistake` / `examType` / `year` / `region` / `createdAt`），另含 `idiomIds`（数组、**至少一条**、uuid，与 `mistakes[].idiomIds` 同构，对应 `user_example_idiom`）；是用户录入题的全集；导入后 `imagePath` 恒为 NULL。`mistakes[]` 通过 `userExampleId` 关联到 `userExamples[]`；导入时两者各自按 `id` 去重，冲突保留本机；`idiomIds` 引用的成语必须在内容表存在，否则按孤儿处理并上报，不猜测。未标错的录入题只在备份的 `userExamples[]` 中，不在 `mistakes[]`。
- `data.json` 的 `tags` 明确为 `mistake.tagNames` 的**去重投影**（§4.1 无独立 tag 表，只有错题行内 JSON 字段）；它只用于展示与校验，不参与按 `id` 去重的主键判定，合并时以 mistake 记录内的 `tagNames` 为准。
- `schemaVersion` 从 1 起；导入时版本高于当前支持 → 拒绝并给红错误条（硬错误），不猜测字段。
- 冲突合并（P22「合并」）：按 `id` 去重，**同 id 保留本机记录**（与 P22 文案「同一道题以本机记录为准」一致），不做时间比较。
- 覆盖（P22「覆盖」）：先写临时库、校验通过后整体替换；替换前自动留一份 `backup-before-import-*.zip` 在缓存目录，失败可回滚。
- 导出不含题库本身（P15 明写「不含题库本身」）；但**用户录入题 `userExamples[]` 必须导出**（属用户数据，与错题同命运），不受「不含题库」约束。
- `manifest.counts`（v1.5）为 `{mistakes, userExamples, reviews, idiomStates, scopes}`，各项须与 `data.json` 对应数组实际条数一致；`validate_schema.py` 逐项断言。

### 4.4 题库包

- 源数据在 `content/`，`build_pack.py` 产出 `pack-vX.Y.Z.zip`：`idioms.json` + `examples.json` + `manifest.json`（版本、条数、sha256，算法见 4.5）。**v1.2 决策：`manifest.sha256` 是整包唯一的合并摘要字符串，无旁车 `.zip.sha256`；P16 增量下载只随包携带 manifest，合并摘要必须进包才能端到端校验（依据 §4.5）。**
- App 内置一份初始包（随安装包内置的**真实题库**，离线底座）。**三级兜底，优先级不可颠倒**（产品 v1.4 决策 4 / 4.1 全局行）：①内置包 → ②联网获取更新 → ③标注 TEST 的 mock（只在前两者都拿不到时兜底）。
- **触发方式（产品 v1.4 拍板乙 + 同日追加拍板）**：每次进入 P03 成语库或 P06 例题列表都自动尝试拉取一次（**每次进入触发一次**，不是安装后仅一次；不做后台定时拉取）。成功即更新题库；失败回落内置包——版本号不变、界面给可重试提示；用户也可在 P16 手动点「检查题库更新」重试。自动拉取不改变页面栈、不阻断浏览（拉取过程中内置包内容照常可读，信息架构 v1.2 §4.2）。联网用途仍只「题库获取」这一处（另一处为备份另存网盘），自动拉取是触发方式变化，**不新增联网点**。
- 下载形态仍为增量包：自动拉取与「检查题库更新」都只拉增量包，manifest 承载合并摘要做端到端校验（§4.5）。增量包的技术定义（版本门控 + 整包替换，不做行级 diff）与分发托管见 §4.6。
- **mock 态显示口径（产品 v1.4 拍板丙，E5 / E6）**：连内置包也没有、且联网获取失败时才用标 TEST 的 mock；此时 P16 版本号位置显示「测试数据（TEST）」，其下方写 mock 的**实际条数**，并注明「题库未获取成功」。mock 必须明确标注 TEST、不得冒充真实真题；mock 条数单独显示，不与真实题库条数混写。mock 态与「回落内置包」态不是同一种状态，不共用文案（信息架构 v1.2 §5.4 拆两行）。mock 数据为随包测试样例（可复用 `shared/fixtures/` 样例），只在①②都不可用时加载。
- 包校验失败（sha256 不匹配、manifest 字段异常、下载中断）= **橙＝可恢复异常**：保留当前内置包，版本号保持不变，主按钮为「重试」（P16 屏口径：橙＝可恢复；版本号不变，主按钮是重试；依据设计规范 v1.3 §2.4 与 `高保真空态与异常态-emerald-D-v2.html` 的 P16 屏）。不得给「稍后再试」这类无退路文案。

### 4.5 交换 schema、数据库迁移与共用 fixtures（实现细节，已定）

**交换格式 schema（`shared/schema/`）**

| 文件 | 内容要点 |
| --- | --- |
| `backup-manifest.schema.json` | `schemaVersion`(int，从 1 起)、`appVersion`、`build`、`exportedAt`、`counts`{mistakes,**userExamples**,reviews,idiomStates,scopes}、`sha256`（data.json 规范化摘要）。**无** `imagesIncluded` 字段。`userExamples` 为 v1.5 新增可选键，兼容旧备份。 |
| `backup-data.schema.json` | `mistakes[]`（字段同 §4.1 `mistake`，导入后 `imagePath` 恒为 NULL）、**`userExamples[]`（v1.5 新增，字段同 §4.1 `user_example`，导入后 `imagePath` 恒为 NULL；v1.7 增 `idiomIds` 至少一条）**、`reviews[]`（对应 `review_log`）、`idiomStates[]`（对应 `idiom_state`）、`scopes[]`（对应 `exam_scope`）、`tags[]`（`mistake.tagNames` 去重投影）。主键均为 uuid 字符串。`userExamples` 为可选数组，兼容旧备份。 |
| `user-examples.schema.json`（v1.5 新增） | 字段对齐 §4.1 `user_example`（`id` / `imagePath` / `ocrText` / `stem` / `optionA..D` / `myAnswer` / `isMistake` / `examType` / `year` / `region` / `createdAt`），v1.7 增 `idiomIds`（数组、至少一条、uuid，必填）；描述用户拍照录入题这一**用户数据**，供备份与双端交换共用。 |
| `pack-manifest.schema.json` | `schemaVersion`(int，从 1 起)、`packVersion`、`builtAt`、`counts`{idioms,examples}、`sha256`（**单一合并摘要字符串**，v1.2 决策，非双字段对象）。 |
| `idioms.schema.json` / `examples.schema.json` | 字段分别对齐 §4.1 的 `idiom` / `example`（系统自带题库，**内容表**）。 |

**sha256 算法**：对参与校验的 JSON 做规范化后取 SHA-256 十六进制摘要并写入 manifest。规范化口径：UTF-8 编码；对象键按字典序升序；去除无意义空白；数组按 `id` 升序（由 `ingest_content.py` 写入时排序保证，`canonical.py` 的「保持原序」与之对齐）。题库包（v1.2 决策，**单一事实源**）：`manifest.sha256` 直接承载整包**合并摘要**——将 `idioms.json` 与 `examples.json` 按文件名排序（`examples.json` < `idioms.json`）后各自规范化并拼接，再取 SHA-256；算法唯一实现为 `tools/canonical.py:combined_digest`，`build_pack.py` 写值与 `validate_schema.py` 校验复用同一函数，**不生成旁车 `.zip.sha256`**（旁车在 zip 外，P16 增量下载不随行，无法端到端校验）。备份包对 `data.json` 规范化后取 SHA-256。检查更新 / 导入时重算并与 manifest 比对：题库包不一致按橙＝可恢复异常处理（§4.4）；备份包不一致或 schemaVersion 超版按红＝硬错误拒绝（§4.3、§8.3）。

**数据库迁移路径与版本表**

- DB schema 版本从 **1** 起，与交换格式 `schemaVersion` 各自独立编号、互不引用。版本表：`v1`＝初始 **10 张表**结构（历史口径不改，见 `shared/schema/migrations.json`）；`v2`（v1.5 方案）＝在 v1 基础上新增 `user_example` 表、`mistake` 增 `userExampleId` 可空列；`v3`（v1.7 方案）＝在 v2 基础上新增 `user_example_idiom` 关联表（`userExampleId` + `idiomId` 联合主键），形成当前 **12 张表**结构。`v4` 起预留。
- **v2 迁移方案（2026-11-20 已实施）**：① 新增 `user_example` 表（§4.1 字段，可空列留空、`isMistake` 默认 false）；② `mistake` 表 `ALTER TABLE ADD COLUMN userExampleId TEXT`（默认 NULL，历史行保持 NULL）；③ 不删除、不改名、不改任何既有列类型；④ 双端各写 forward 迁移与回读校验，校验目标表行数、索引存在、外键可解析；⑤ 配套「v1→v2 造数据」单测（§11.1）覆盖正常路径与中断回滚。迁移实现、`migrations.json` 版本登记与代码落地已随本版内修订完成（阶段 2 前置）。
- **v3 迁移方案（随 2.5 实施）**：① 新增 `user_example_idiom` 表（`userExampleId` TEXT + `idiomId` TEXT，联合主键，两列各建索引）；② 防御性回填——对既有 `mistake.userExampleId` 非空的行，按该 `mistake` 的 `mistake_idiom` 成语写入关联（已存在则跳过），回填只补不删；③ 不删除、不改名、不改任何既有列；④ 双端各写 forward 迁移与回读校验（表存在、联合主键、回填行数符合预期、`idiomId` 可解析）；⑤ 配套「v2→v3 造数据」单测覆盖正常路径与中断回滚。实现合并后 `migrations.json` 的 v3 状态由 `planned` 改 `shipped`。
- Android：`@Database(version = 3, ...)`，v2 的 `DbMigrations.MIGRATION_1_2` 保留，新增 `MIGRATION_2_3`（登记于 `DbMigrations.ALL`）；iOS：GRDB `DatabaseMigrator` 注册 `"v3"`。两端 schema 演进只增不改，导出 schema 与迁移 DDL 由单测对齐。
- 只做 additive 迁移（增表 / 增列带默认值）；破坏性迁移必须写显式迁移类，并配「v1→v2」「v2→v3」造数据单测（§11.1）。
- DB 版本低于当前 → 执行迁移；高于当前 → 拒绝打开并提示升级 App，不猜字段、不降级写库。§11.1 要求的「v1→v2 造数据」单测在 v2 实施时用真实新增列验证，不引测试专用空迁移替代真实变更。

**`shared/fixtures/` 共用测试数据要点**

- `idioms.json`：3–5 条成语，覆盖拼音首字母边界与褒 / 贬 / 中三类感情色彩。
- `examples.json`：2–3 条真题，含 1 条「一题多成语」（B3）与 1 条「未关联成语」异常数据（测 P07 空态）。
- `backup/manifest.json` + `backup/data.json`：一份完整备份包样例（2 条 mistake，待复习 / 已掌握各一；2 条 review；3 条 idiomState；2 条 scope；2 条 tag；一条 mistake 的 `imagePath` 非空、另一条为 null，覆盖「图片缺失不阻断导入」）；`manifest.sha256` = data.json 规范化摘要；**不含** `images/` 目录。合并去重用例（同 id 两条记录）在单测内造数据——合法备份包不得含重复 id，`validate_schema.py` 会直接拒绝。**v1.5 口径**：`userExamples[]` 与 `counts.userExamples` 为可选新增字段，既有 fixture 暂不含该数组以兼容旧备份；含录入题的样例与 `userExampleId` 外键断言在数据层单测内造数据，不改动 fixture 的 sha256。
- `pack/manifest.correct.json` 与 `pack/manifest.corrupt.json`：共用 `idioms.sample.json` / `examples.sample.json`；前者 `sha256` = 重算合并摘要（成功分支，应通过），后者 `sha256` 被篡改（失败分支，必须被 `validate_schema.py` 判为不匹配）；两者结构均合法并过 `pack-manifest.schema.json`。
- 断言点：合并同 id 保留本机、覆盖失败回滚、sha256 不匹配、schemaVersion 超版拒绝、P10 原图占位。

### 4.6 题库包分发与增量更新协议（v1.4 技术侧决策，消解「分发托管未定义」缺口）

§4.4 定了触发方式与三级兜底，本节定「从哪拉、拉什么、怎么校验、怎么发布」。联网用途仍只「题库获取」这一处，本节不新增联网点。

**托管选型（已定）**

- 生产源 = **国内对象存储**（阿里云 OSS 或腾讯云 COS，实施期二选一，优先团队已有账号者）：bucket 的 `pack/` 目录公共读、其余目录私有；用服务商**默认域名直链**，不绑自定义域名（默认域名免 ICP 备案，绑自定义域名才需备案），不开 CDN（首发单包 KB–MB 级，无加速需求）。
- 依据：目标用户为国内考公考编考生，国内可达性必须稳定；纯静态 GET、零后端逻辑、零服务器运维；按量付费无固定月费。阿里云 OSS 默认域名对浏览器访问强制加 `Content-Disposition: attachment`（2025-12-22 起指定地域新建 bucket 的政策），对 App 内 HTTP 客户端下载无影响，zip 本就走下载。腾讯云 COS 默认域名政策同类，实施期复核一次。
- GitHub Releases **仅作团队侧 CI 产物存档与镜像**，不作 App 内生产源（国内访问不稳定）。自建服务器否决：无动态接口需求，徒增运维与攻击面。Cloudflare 系海外托管同理否决（国内可达性）。
- URL 布局（bucket 名与 endpoint 为实施期配置项，不写死在本文）：
  - 通道清单：`https://<bucket>.<endpoint>/pack/latest.json`
  - 题库包：`https://<bucket>.<endpoint>/pack/pack-vX.Y.Z.zip`
- 两个源地址在 App 内为**编译期常量**（双端各一处，放数据层配置）；换源随 App 版本更新，不做远程配置接口、不引第三方重定向。

**增量包协议（已定：版本门控 + 整包替换，不做行级 diff）**

- 两段式拉取：① GET `latest.json`（轻量通道清单）；② 比较 `packVersion`，仅当远端 > 本机才下载 pack zip。「增量」= 按需拉取、无更新不重复下载；包体为**整包替换包**。
- `latest.json` 字段（新增 schema `shared/schema/channel-manifest.schema.json`，阶段 5 实施）：`schemaVersion`(int ≥1)、`packVersion`(`^v\d+\.\d+\.\d+$`)、`builtAt`、`counts`{idioms,examples}、`sha256`（合并摘要，算法同 §4.5）、`sizeBytes`(int，zip 字节数)、`packFile`（相对文件名，指向同目录 zip，**不允许绝对 URL / 跨域**）。除 `packFile` / `sizeBytes` 外与 pack-manifest 同构；**包内 manifest 仍是校验事实源**，latest.json 只是通道提示，两者不一致时以包内 manifest 为准并按橙处理。
- 版本比较：`vX.Y.Z` 数值逐段比较。远端 > 本机 → 下载；相等 → P16「已是最新版本」（绿）；更低 → 忽略（防回滚 / 防误配置）。
- 不做行级 diff 的理由：① 题库精简起步、单包 KB–MB 级，整包下载成本可忽略；② 行级 diff 需墓碑机制与合并冲突处理，复杂度与校验面陡增；③ 既有合并摘要（§4.5）正是整包端到端校验，行级 diff 会推翻 sha256 单一事实源决策；④ 整包替换 + 临时库校验 + 原子切换天然可回滚，与 §4.3 覆盖语义同构。
- 下载与导入链：下载 zip → 重算合并摘要比对 `manifest.sha256` → schema 校验 → 导入临时库 → 原子切换。任一步失败 = **橙＝可恢复**：保留当前包、版本号不变、P16 主按钮「重试」（§4.4）。`schemaVersion` 超 App 支持 → 同样橙，保留当前包并提示升级 App，不猜字段（区别于备份包的红＝硬错误：题库包失败不得阻断浏览）。
- 导入影响面：只替换内容表（`idiom` / `example` / `idiom_scope` / `example_idiom`，含 FTS 重建）；**绝不触碰用户表**（`user_example` / `user_example_idiom` / `mistake` / `mistake_idiom` / `review_log` / `idiom_state` / `settings` / `exam_scope`）。v1.5 扩展说明：用户拍照录入的题存于 `user_example`，即使与题库包内系统真题题干相同也**不得被覆盖或替换**；成语详情页双来源（用户录入 + 系统题库）并列展示，导入器不得合并两者。
- idiom uuid 跨版本稳定（内容侧硬约定）：同一成语在不同包版本中保持同一 uuid（入库时分配并持久化在 `content/`）；已发布成语原则上只修正不删除；若确需删除，被本机 `mistake_idiom` 或 `idiom_state` 引用的 idiom 行必须保留（孤儿保留，不重建其内容范围链接、不在库列表展示），保证错题归属与学习状态永不悬空。
- 初始导入实现：Android 使用系统 ZIP API，iOS 数据库模块使用 ZIPFoundation 0.9.19（SPM 精确锁定）；只接收根目录三个指定 JSON 文件，不把 ZIP 路径解压到文件系统。限制压缩输入与展开数据大小，拒绝重复路径、额外文件、截断与 CRC 异常；合并摘要和 schema 任一不符均不得写正式库。
- `idiom_scope` 只引用已有 `exam_scope`，导入器不创建或修改用户范围。按成语 `scopes` 匹配考试类型；省考必须有已选省份且有该省例题的关联证据，`province=NULL` 不代表全部省份。P01/P14 保存范围后由数据层基于已校验的当前包重建内容范围链接；不得因初始化先后顺序丢失链接。
- 网络行为约束：仅 HTTPS、不禁用证书校验；超时 connect 10s / read 30s（技术默认值，以本文为准）；只允许同源重定向；请求不携带任何用户标识、学习数据或自定义追踪头（纯 GET）；自动拉取不阻断页面、不改页面栈（§4.4）；并发去重——上一次拉取仍在途时，新的进页不重复发起请求（不改变「每次进入触发一次」的计数口径）；失败后不自动重试，重试入口只有 P16 手动。
- 发布流程（团队侧，不在 App 内）：`build_pack.py` 产 pack → **先上传 `pack-vX.Y.Z.zip`，后更新 `latest.json`**（顺序保证客户端不会读到指向不存在文件的清单）；旧版本 zip 不删除，回滚 = 把 latest.json 指回旧版本。上传凭证只存在团队侧发布环境，不进仓库、不进 App。

**rgba 类 token 在生成脚本中的转换规则（必须实现）**：

- 形如 `rgba(r,g,b,a)` 的字符串，`r/g/b` 为 0–255 整数，`a` 可能是 `.55` / `.12` / `.14` / `.38` / `.42` / `.62` 这类省略前导零的小数；脚本统一按 float 解析（`.55` → `0.55`），照抄值不改。

### 7.0 Swift / SwiftUI 开发前置规则（2026-11-18 补充）

以下区分官方设计指导与本项目验证要求；阅读最新文档不等于升级编译器、SDK 或最低系统版本。

**官方指导的采用口径**

- 以 Swift 官方 [API Design Guidelines](https://www.swift.org/documentation/api-design-guidelines/) 为命名依据：调用处清晰优先于简短；类型/协议用 UpperCamelCase，成员用 lowerCamelCase；参数按角色命名并使用清晰标签；有副作用的方法使用动词，变更与返回副本区分为 `sort` / `sorted` 等；布尔属性表达断言，避免只按返回类型重载。
- 先读当前 SDK 的真实声明，再使用 API：核对参数标签、泛型约束、Optional、`get`/`set`、actor 隔离和 availability；不能根据相似 API 或示例推断可用性。Optional 的范围匹配应先解包或显式匹配 `.some`，不得用强制解包隐藏空值分支。
- SwiftUI 环境值并非全部可写。[accessibilityReduceMotion](https://developer.apple.com/documentation/swiftui/environmentvalues/accessibilityreducemotion) 明确为 `var accessibilityReduceMotion: Bool { get }`；不得用 `.environment(\.accessibilityReduceMotion, true)` 注入。系统无障碍状态须通过已核实的受支持途径设置，并在测试中断言实际生效；未核实的模拟器 defaults 命令不能写成既定方案。
- 并发设计明确 UI 主 actor 与共享可变状态的归属，遵守编译器的隔离及 Sendable 检查；不得以 `@unchecked Sendable`、`nonisolated(unsafe)` 或降低语言模式消除报错而不证明安全性。[Swift 6.2 发布说明](https://www.swift.org/blog/swift-6.2-released/) 中默认 MainActor 隔离、`@concurrent` 等是特定工具链/选项能力，不得直接套用到旧工具链。
- 官方推荐为声明写文档；本项目不机械补注释，保留自说明命名，仅对非显然约束、复杂度或安全不变量写必要的简短说明，不以注释代替测试。

**官方指导的采用口径**

- 以 Kotlin 官方 [Coding conventions](https://kotlinlang.org/docs/coding-conventions.html) 为基础（本次读取页面标注更新于 2026-09-23）：四空格缩进；类/对象 UpperCamelCase，普通函数/属性 lowerCamelCase，常量按官方常量规则命名；返回 `Unit` 的 `@Composable` 函数使用 UpperCamelCase，不得误改为普通函数命名。单类文件与类同名，多声明文件按职责命名，避免无含义的 Util；相关声明聚合但不堆成巨型文件。
- 不变引用优先 `val`，不需修改的集合对外使用只读接口；只读接口或 `val` 不保证底层对象深度不可变或线程安全。多个同类型参数、布尔参数在含义不明显时使用命名实参；嵌套 lambda 显式命名参数，避免 `it` 歧义；默认参数优先于无必要的重载。
- 先检查当前依赖源码/签名的接收者、成员与扩展函数区别、默认参数、可空性、可见性和 API level，再调用；Java 平台类型跨公开边界显式声明 Kotlin 类型及空值契约。不以 `!!`、伪造非空 Context 或任意默认值掩盖错误。
- 按官方 [Compose compiler migration guide](https://kotlinlang.org/docs/compose-compiler-migration-guide.html)，Kotlin 2.0 起 Compose 编译器与 Kotlin 同仓发布，使用同版本 `org.jetbrains.kotlin.plugin.compose`，并应用于每个使用 Compose 的模块；Compose BOM 不等于编译器插件版本。最新文档中的新语法、AGP 9 内建 Kotlin 配置不得直接套用到本项目 AGP 8。
- 按 Android 官方[协程最佳实践](https://developer.android.com/kotlin/coroutines/coroutines-best-practices)，不得吞掉 `CancellationException`；捕获宽泛异常时必须保留取消传播。取消不是业务失败，不应被通用重试或错误提示逻辑消化。

## 9. 错误处理与可访问性

### 9.1 三级语义（沿用设计规范，不许自创）

| 级别 | 颜色 | 用在哪 | 是否给退路 |
| --- | --- | --- | --- |
| 可恢复异常 | 橙 `--warnfg` | 相机权限被拒（E19）、识别不出文字（E20）、题库检查失败 / 下载中断（E18） | 必须给 2–3 条退路；主按钮是「重试」，版本号不变（P16 屏口径） |
| 硬错误 | 红 `--errfg` | 备份包损坏（含 sha256 不匹配、schemaVersion 超版）、数据库迁移失败、写入失败 | 给重试或回滚，不给「稍后再试」这种空话 |
| 纯信息 | 中性 | 空态、0 数据、识别行数 | 不给按钮或只给导航 |

- 省考未选省份（E04）已随产品 v1.6 省份口径变更消解：省考勾选时省份默认全选、省份作筛选维度可增减、省考内容正常显示；不再有「未选省份」异常态与橙警示，故不再列入上表橙＝可恢复异常。
- 任何异常都必须落到具体文案，禁止只弹 toast「操作失败」。
- 崩溃与异常**不得**上报到任何第三方（不上传统计、不接崩溃平台）。

### 9.2 空态与异常态

44 屏已出稿（D 稿 E01–E22），实现时逐条对齐；三条按规则不出稿的（P15 系统面板空、P10 原图丢失已在主态、P16 已是最新已在主态）按文档说明处理，不另造。

### 9.3 可访问性

- 对比度沿用设计规范 7.1：正文 ≥ 4.5:1，大字 ≥ 3:1；禁用态与骨架屏按 7.3 豁免。新增任何色值必须脚本复算（历史教训：手算错过三次）。
- 命中区 ≥ 44×44（Android 48dp）。设计稿里 7/11 的顶部按钮、2/6 的徽标这类小构件，实现时用 padding 撑到命中区，视觉尺寸不变。
- 系统字体缩放：Android 到 200%、iOS 到 AX3，页面必须仍可用（卡片内文字换行，不裁切）；30px 数据大字允许按容器缩放，不做等比缩小全部文字。
- 语义标签：TalkBack / VoiceOver 读「按部就班，àn bù jiù bān，贬义，高频」，不逐字读拼音字母；装饰性 SVG 一律 `contentDescription = null` / `accessibilityHidden`。
- 动效：只保留「按下反馈 + 弹层进出 + 骨架流光」，全局响应 `reduce motion`；不做自动轮播。**骨架流光须响应系统 reduce motion：未开启时按设计规范 v1.3 §5.10 的 `1.5s ease-in-out infinite` 高光横移实现；开启时降级为静态色块（用既有 `--skel`，不新增色值）。**

## 12. 代码规范

### 12.1 组织

- 分层：`ui`（Composable / View）→ `domain`（用例、状态机）→ `data`（Repository、DAO）。UI 层不出现 SQL、不出现业务阈值。
- 一个页面对应一个 `ViewModel` / `ObservableObject`，页面级状态不跨页共享；跨页共享只走数据库和 `settings`。
- 命名：页面 `P05IdiomDetail`、构件 `CButton` / `CWarnBar` / `CModalSheet`（前缀 `C` 表示 design system），两端同名，便于对照排错。

### 12.2 禁止事项（硬性）

1. 页面里硬编码颜色、字号、圆角、间距（只能取令牌）。
2. 引入任何账号 / 埋点 / 崩溃上报 / 广告 SDK。
3. 任何形式上传学习数据；OCR 走云端。
4. 用 emoji、图标字体、位图图标替代 SVG。
5. 接 hover 或鼠标态。
6. 在二级页与详情页放相机入口。
7. 一屏出现两处红动作，或用橙表达「纯信息」。
8. 自造规范外数值（含「看起来差不多」的 8px、12px）。
9. 打印含学习内容的日志到 release 包。
10. 改文档口径来迁就实现。

### 12.3 提交与版本

- 分支：`main`（可发布）/ `feat/<page-or-feature>` / `fix/<issue>`。
- 提交信息：`feat(P20): 候选默认勾选最匹配一项`，类型限 `feat|fix|refactor|test|docs|chore`。
- 每次发布写 `CHANGELOG.md`，关联产品版本与题库包版本（P16 显示的就是后者）。
- 设计系统改动必须先升设计规范版本号，再进代码。

## 14. 完成定义（DoD）

一个页面算完成，需要同时满足：

1. 颜色、字号、圆角、间距、图标尺寸全部来自令牌，代码里搜不到十六进制色值和裸数值。
2. 浅色 / 深色各比对一遍基线图。
3. 主态 + 对应空态/异常态都实现（按 IA 5.4 与 D 稿）。
4. 命中区 ≥44、系统字体 200% 下不破版、TalkBack/VoiceOver 能读完关键信息。
5. 无 hover、无 emoji 图标、无网络请求（拍照链路尤其要抓包确认）。
6. 单测覆盖该页状态机分支；手工结果写在验收记录里。
