## 阻断项 1：OCR 样张实测（代理完成，18/20＝90%）

- 素材：用户给 20 张真实卷面照片 `docs/OCR-DEMO/1..20.PNG`（未裁剪）。
- 引擎：本机只有 Windows 自带 `Windows.Media.Ocr`（zh-Hans-CN，离线），**不是** PaddleOCR/Vision，因此记为「代理实测」。
- 方法：灰度 → 2× LANCZOS → autocontrast → 锐化 1.4 → OCR（词框）→ 版面重建（按 y 聚行、x 间距 42px 切格、A→B/C→D 邻格补位）→ 判「题干+四选项是否齐全」。
- 结果：18/20 通过，90.0%；P50 65ms / P90 88ms；`tools/ocr_passrate.py --target 0.9` → PASS。
- 两个失败：8 号缺 C 行、14 号缺 B/C 两行，都是整行漏识，照片本身五要素齐全（已目视核对）。
- 关键发现：同一张图原尺寸直跑把「高质量发展」读成「高质友展」并丢 C 行；2× 放大后全对。→ **P18 裁切后按短边 ≥1400px 上采样再识别**，已写进规范 §2.3 与 Android OcrEngine 契约注释。
- 记下一条踩坑链：Windows OCR 在 PS5.1 需显式 `[Type, Assembly, ContentType=WindowsRuntime]` 投影 Storage/BitmapDecoder 等类型；`Add-Type System.Runtime.WindowsRuntime` + AsTask 泛型 await；PS 写出的 JSON 带 BOM，Python 侧必须 `utf-8-sig`。
- 落盘：`docs/OCR实测记录.md`（结论/逐张表/失败性质/限制/下一步）、`docs/OCR样张实测方案.md` 状态更新、`docs/OCR-DEMO/README.md`、`样张登记表.csv` 已填版式/分辨率/完整性/缺项/耗时（来源/光线/角度/干扰四列未记录，留空不臆测）。
